Cross-Cutting Concerns

Komponen yang melintas batas klaster dan mempengaruhi seluruh sistem

Approvals — Workflow Engine

Modul Approvals dirancang sebagai trigger-agnostic engine. Domain lain memanggil ApprovalGate dengan opaque trigger key. Saat ini sudah terhubung dengan Purchasing (PO approval). Berpotensi dikembangkan ke Receivables (credit override), Canvassing (diskon khusus), dan Outbound (dispatch besar).

  • Purchasing sudah listen event ApprovalCompleted via boot()
  • Policy per tenant — jumlah level approval dapat dikonfigurasi
  • Inbox approval dengan permission khusus decide

StockMovementRecorder — Shared Service

Service tunggal yang menangani semua mutasi stok. Dipakai oleh Inventory (manual), Purchasing (GRN in), Outbound (dispatch out), dan transfer antar gudang. Pola ini mencegah double-accounting dan menjaga konsistensi stock_levels.

  • record() — in/out/adjustment manual
  • transfer() — dua kaki (out source + in destination) atomik
  • FIFO/FEFO picking strategy untuk out tanpa explicit batch
  • Batch/lot tracking: batch_number + expiry_date per movement

ShipmentStatusNotifier — Event Bus

Komponen terpusat yang mengirim notifikasi + event saat status delivery order berubah. Digunakan oleh TripObserver (transisi trip-level) dan PodController (transisi delivered). Mencegah drift antara dua jalur update.

  • Kirim GenericNotification ke semua user dengan orders,view
  • Dispatch ShipmentStatusChanged event (dapat didengarkan modul lain)
  • Safe dari double-announce karena where status=$from filter

Multi-Tenancy — Stancl Tenancy

Setiap tenant memiliki database terpisah. Modul diinstall/uninstall per tenant. CentralUser + per-tenant User dihubungkan oleh global_id. Reseller dapat mengelola beberapa tenant. Storage di-isolasi per tenant.

  • Central domain: super admin, reseller management
  • Tenant domain: operational modules, isolated DB
  • modules:migrate untuk menjangkau tenant lama saat rilis modul baru
  • Purge grace period 30 hari setelah uninstall

Rekomendasi Pengembangan

Prioritas fitur dan modul berdasarkan analisis gaps dan kebutuhan industri

Pengadaan & Gudang
Prioritas Tinggi
  • Implementasi GrnConfirmationService: konfirmasi GRN → auto stock-in via StockMovementRecorder (desain sudah ada di docs/modules/po-grn-design.md)
  • Frontend 5 halaman PO+GRN (Index, Create, Show PO, Create GRN, Show GRN) dengan progress bar per PO
  • Inventory Transfer frontend (halaman sudah dirancang, StockMovementRecorder.transfer() sudah ada)
  • Integrasi Approvals ↔ Purchasing: PO besar otomatis trigger ApprovalGate sebelum dikirim ke supplier
  • Stock Reservation: link StockReservation ke Outbound pick-list (model sudah ada, belum dipakai)
Distribusi & Logistik
Prioritas Tinggi
  • Outbound: validasi pick quantity vs StockLevel, integrate StockMovementRecorder untuk dispatch (stock out saat pick-list dispatch)
  • Route Optimization: integrasi solver VRP nyata (OSRM/Google OR-Tools/Valhalla) — saat ini endpoint optimize perlu backend algorithm
  • Receivables: implementasi payment creation + void, aging report query (modul sudah ada, butuh UI + business logic)
  • Invoicing → Receivables link: saat invoice issued, auto-create outstanding di Receivables
Fleet & Compliance
Prioritas Sedang
  • Driver Scoring: implementasi DetectDrivingEvents listener (harsh brake detection dari GPS delta, speeding dari speed attribute Traccar, idle dari position tanpa movement)
  • Driver Scoring: leaderboard page + incentive award workflow + settings konfigurasi threshold per tenant
  • Maintenance: prediktif scheduling dari odometer/jam pakai (kendaraan sudah punya field ini) — buat scheduled command cek threshold
  • Fleet: fuel efficiency analytics — konsumsi per km per kendaraan, trend bulanan
Intelligence & Control
Prioritas Sedang
  • Executive Dashboard: implementasi KPI query di ExecutiveDashboardController — OTD dari delivery_orders, utilisasi dari trips, aging dari Receivables, turnover dari stock_movements
  • Dashboard: scheduled aggregation job (daily snapshot) agar query BI tidak memperberat OLTP saat peak hours
  • Approvals: extend ke Receivables (credit override perlu approval), Canvassing (diskon khusus per kunjungan)
  • Notification center: push notification / email untuk approval pending dan overdue AR
Sales & Commercial
Prioritas Sedang
  • Trade Promotions: implementasi sync realisasi dari Orders (volume per produk per customer per periode) — endpoint /programs/{program}/sync sudah ada, butuh query logic
  • Trade Promotions: settlement flow (transfer ke rekening distributor atau credit note) + integrasi Approvals untuk settlement besar
  • Canvassing: integrasi order capture di lapangan — salesperson bisa input SO dari visit yang langsung masuk ke Orders
  • Rental: integrasi Billing untuk generate invoice rental otomatis
Master Data (Enhancement)
Prioritas Rendah
  • Product: price list per customer tier / kanal distribusi (dibutuhkan oleh TradePromotions dan Canvassing order capture)
  • Partners: customer tier / segment (key account, regular, modern trade) untuk routing promosi dan credit limit berbeda
  • Partners: payment terms per customer (net-30, net-60) yang dipakai Receivables untuk aging calculation
Modul Baru yang Disarankan
Future
  • Payables / AP: pasangan dari Receivables untuk hutang usaha ke supplier — pembayaran PO, aging hutang, due date tracking
  • Customer Portal: web portal untuk customer track own orders, download invoice, lihat history pengiriman (perlu auth terpisah / magic-link)
  • Sales Order (SO): dokumen penjualan sebelum Delivery Order — untuk pipeline yang butuh order confirmation, partial delivery, backorder tracking
  • Returns & Claims: retur barang dari customer ke gudang dengan rekonsiliasi stok dan kredit nota otomatis
  • HR / Payroll Basic: kalkulasi gaji driver dari uang jalan (Billing) + insentif DriverScoring — modul ringan bukan full HRIS
