⚡ Cancel setelah Dispatch → reverse movement: buat StockMovement in kembali ke gudang sumber dengan reference TRF-…-CANCEL
StockTransferService::dispatch(): Dalam satu DB::transaction — buat 2 StockMovement per item (type:'out' di from_warehouse, type:'in' di to_warehouse), update quantity_sent, set status='in_transit', set dispatched_at=now(). Kedua movement punya source_type:'transfer' dan source_id: $transfer->id.
StockTransferService::receive(): Hanya buat movement in di to_warehouse untuk qty yang benar-benar diterima (bisa kurang dari sent), update quantity_received, set status='completed'.

Titik Integrasi & Keputusan Kode
dispatch() → Validasi StockLevel.on_hand ≥ quantity_requested sebelum execute. Buat movement out di from_warehouse (decrement on_hand), lalu movement in di to_warehouse (increment on_hand). Keduanya source_type:'transfer'.
receive() → Qty diterima sudah dibuat saat dispatch (movement in). Jika qty_received ≠ qty_sent (barang rusak/hilang), buat movement out di to_warehouse sebesar selisihnya dengan reference TRF-…-LOSS. Update quantity_received, set completed_at.
cancel() setelah dispatch → Buat reverse movement in di from_warehouse sebesar quantity_sent dengan reference TRF-…-CANCEL. Stok tujuan tidak perlu diubah (movement in ke tujuan tidak pernah dibuat saat dispatch).
Validasi gudang → from_warehouse_id !== to_warehouse_id — diblokir di StoreStockTransferRequest dengan rule different:from_warehouse_id.
StockMovementRecorder → Dipakai langsung oleh StockTransferService — tidak ada perubahan ke kelas ini. Type yang dipakai adalah 'in' dan 'out', bukan 'transfer'.
